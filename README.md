# MYCF711 账号级默认社区健康文件（`.github`）

这个仓库只放一件事：给 **GitHub 个人账号 MYCF711** 名下的仓库，提供一套**通用的 Issue 门禁**。

它不属于任何一个具体插件，也不绑定任何仓库。

## 它是怎么生效的

- 账号下**没有自带 `.github/ISSUE_TEMPLATE/` 的仓库**，在新建 Issue 时会**自动继承**这里的模板。
- 仓库一旦有**自己的** Issue 模板（哪怕只有一两个文件），就**整组覆盖**默认模板 —— 此时这里的模板对该仓库**完全不生效**。
- 所以改这里**不需要给任何业务仓库发版**，也不用改业务仓库的代码、不用重新打包发布；模板是在新建 Issue 时才会被读取的。
- 生效范围只是「新建 Issue 的入口」，不会改动任何仓库已有的内容。

## 两个必须守住的前提

1. **本仓库必须是 public。** GitHub 只会把**公开**仓库当作账号级默认社区健康文件来源。本仓库如果是 private，模板会**静默失效**（没有任何报错，也没有提示）。
2. **路径必须严格符合 GitHub 约定**，多一层目录名、改一个字母都会让模板不被识别。

## 目录内容

| 路径 | 作用 |
| --- | --- |
| `README.md` | 本文件，说明这套默认文件的作用范围与约定 |
| `.github/ISSUE_TEMPLATE/bug_report.yml` | Bug 报告表单（只收可复现的 Bug） |
| `.github/ISSUE_TEMPLATE/feature_request.yml` | 功能建议表单 |
| `.github/ISSUE_TEMPLATE/config.yml` | 关闭空白 Issue 入口 |

本仓库**刻意不包含**：PR 模板、GitHub Actions 工作流、Release 配置、标签（label）配置、许可证文件。这些东西按仓库各自的需要单独放，不放在账号级默认文件里。

## 模板约定

- **不含 `labels`**：目标仓库未必有对应标签，写死标签会导致表单提交异常或标签丢失；也不使用表单级的 `assignees` / `projects` / `type`（`type` 只作为每个表单元素的必填键），不依赖任何仓库级配置。
- **`config.yml` 只写 `blank_issues_enabled: false`**，不写 `contact_links`（联系方式的链接做不到对所有仓库通用）。
- `blank_issues_enabled: false` 的实际效果：对 **Read / Triage** 权限的普通用户，隐藏「空白 Issue」入口，必须走表单；**Write / Maintain / Admin** 权限的维护者仍然能看到并使用那个空白入口（显示为 Maintainers only）。
- 这套模板**不会自动关闭 Issue**，不包含任何自动关闭、超时提醒、机器人打标签的逻辑。

## 门禁的设计意图

账号下多个开源插件热度上来以后，低信息 Issue 变多（只发两张截图、一句「插件失效了」、把 Issue 区当提问区）。

所以这套表单做三件事：

1. **只收能复现的 Bug**：提问、配置求助、闲聊、许愿去项目交流群或 Discussions（如果已开启）。
2. **把排查前置**：「先更新到最新版 → 把现象和截图交给 Agent 排查整理 → 再提交」。普通用户不需要自己把技术细节挖到底，照这个动线走即可。
3. **压掉不可复现的信息**：必填版本、宿主、系统与部署方式、模型或组件、实际现象、期望行为、最小复现步骤，以及**复制的文字日志**（截图只能作补充）。

文案面向普通真人，不写威胁性话术：表单只会拦住明显没准备好就提交的内容，不会因为信息不全就自动关掉 Issue。
